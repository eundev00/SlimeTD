# 슬라임 렌더링

슬라임 몸통·얼굴의 셰이더 구성과, 슬라임끼리 겹칠 때 **먼저 나온 슬라임이 위에 보이게** 하는 그리기 순서(스텐실)를 정리한다.

---

## 1. 해결한 문제

**증상**: 슬라임들이 경로상 가까워지면 실제 3D 공간에서 구체끼리 겹친다. 깊이 테스트만으로 그리면 겹친 부분에 두 메시의 교차선이 드러나 **서로 파고든 것처럼** 보인다.

**해결**: 슬라임을 등장 순서대로 그리고, 스텐실로 **나중 슬라임이 먼저 나온 슬라임이 그려진 픽셀을 덮지 못하게** 한다. 겹쳐 있어도 교차선 없이 먼저 나온 슬라임이 통째로 위에 보인다. 보스는 항상 맨 위다.

**Transform 실제 좌표는 건드리지 않는다.** 타워 타겟팅과 이동 로직에 영향이 없다.

### 예전 방식 (깊이 버킷, 삭제함)

셰이더에서 슬라임마다 clip z를 조금씩 뒤로 미는 방식이었다. 민 거리보다 실제 앞뒤 차이가 크면 순서가 뒤집혔고, 같은 카메라의 다른 물체(타워 등)와의 앞뒤까지 바뀌었고, 간격 값을 맞춰야 했다. 스텐실은 이 셋이 없어 교체했다.

슬라임이 땅에 묻혀 보이던 문제는 렌더링이 아니라 배치 높이 문제였다 (스플라인 높이가 땅 표면보다 낮았다). 지금은 타워처럼 경로의 땅 표면을 레이캐스트로 찾아 그 높이에 세운다 (`WaveSpawner`가 경로마다 한 번 찾아 `BaseSlime.Initialize`에 넘긴다).

---

## 2. 셰이더 구성

슬라임 몸통과 타워는 툰 셰이더 `SlimeTD/SlimeFlatKit`(FlatKit Stylized Surface 사본에 스텐실과 큐브 테두리를 넣은 것)을 쓴다. 외곽선은 쓰지 않는다 (5장).

| 파일 | 용도 | Surface | ZWrite |
|---|---|---|---|
| `Assets/Art/Shaders/SlimeFlatKit.shader` | 슬라임 몸통, 타워 (툰) | Opaque | On |
| `Assets/Art/Shaders/SlimeFace.shader` | 얼굴 | AlphaClip | On |

두 셰이더의 메인 패스에 스텐실 블록이 있다. 값은 머티리얼 속성이고 기본값(Comp Always, Pass Keep)이면 꺼진 것과 같다. 타워는 기본값 그대로 쓴다.

```
Stencil { Ref [_SlimeStencilRef]  Comp [_SlimeStencilComp]  Pass [_SlimeStencilPass] }
```

### 얼굴은 Alpha Clipping이어야 한다

얼굴 텍스처(`T_Slime_Face_XX_Custorm.png`, 1024×1024 RGBA)의 알파 분포를 실측한 값이다.

| 텍스처 | 완전투명 | 불투명 | 반투명 |
|---|---|---|---|
| Face_01 | 75.6% | 5.1% | 19.3% |
| Face_07 | 78.3% | 8.9% | 12.8% |
| Face_17 | 78.2% | 9.9% | 11.9% |

- **순수 Opaque 불가**: 76~78%가 완전투명이라 1024×1024 사각형이 몸통을 덮는다
- **ZWrite Off 불가**: 얼굴이 깊이를 안 쓰면 같은 슬라임 몸통과의 앞뒤가 깨진다
- **Alpha Clipping 채택**: 투명 픽셀은 discard하면서 ZWrite On을 유지한다. discard된 픽셀은 스텐실도 쓰지 않는다

반투명 12~19%는 눈·입의 안티에일리어싱 경계다. 클리핑은 임계값으로 잘라내 계단이 생기지만, `_AlphaToMask: 1`(alpha-to-coverage)이 Mobile 퀄리티의 MSAA 2×와 함께 동작해 경계를 완화한다. **MSAA를 끄면 얼굴 경계가 거칠어진다.**

## 3. 그리기 순서 (스텐실)

### 원리

1. 슬라임은 등장 순서대로 그린다 (`Renderer.sortingOrder`가 작을수록 먼저)
2. 슬라임마다 스텐실 값을 받는다. 먼저 나온 슬라임일수록 크다
3. 셰이더는 `내 값 >= 그 픽셀에 이미 쓰인 값`일 때만 그리고(`GreaterEqual`), 그리면 내 값으로 바꾼다(`Replace`)

먼저 그린 슬라임이 큰 값을 써 두므로, 나중 슬라임은 실제로 더 앞에 있어도 그 픽셀을 덮지 못한다. 같은 슬라임의 몸통·얼굴은 값이 같아 서로 통과하고, 그 사이 앞뒤는 깊이로 정한다.

### 배정 (`SlimeDrawOrderService`)

```
보스        → sortingOrder 0, 스텐실 255     (항상 맨 위)
일반 슬라임 → sortingOrder 1~254, 스텐실 254~1 (등장 순서대로)
```

- 스텐실이 8비트라 일반 슬라임은 동시에 254마리까지 순서를 구분한다. 순번이 끝까지 차면 살아 있는 슬라임만 등장 순서대로 다시 매긴다
- 슬라임이 죽거나 풀로 돌아가면 목록에서 빠진다
- 보스가 여러 마리면 보스끼리는 순서를 구분하지 않는다 (동시 등장 1마리 전제)

### 값 전달 경로

```
BaseSlime.Initialize()
  └ SlimeDrawOrderService.Add(drawOrder, renderGroup)
      └ SlimeDrawOrder.Set(sortingOrder, stencilRef)
          ├ 모든 렌더러 sortingOrder
          └ 머티리얼 인스턴스 _SlimeStencilRef
```

`SlimeDrawOrder`는 슬라임 하나의 렌더러와 머티리얼 인스턴스를 들고 값만 넣는다. `BaseSlime`이 `Awake`에서 만들고, 풀 반환·파괴 때 서비스에서 빼며, 파괴 때 머티리얼 인스턴스를 지운다.

### 머티리얼 인스턴스와 큐

- **`sortingOrder`가 그리는 순서를 정하는 건 Transparent 큐뿐이다.** 그래서 `SlimeDrawOrder` 생성자가 처음 한 번 머티리얼을 인스턴스로 만들어 Transparent 큐(몸통 3000, 얼굴 3001)로 옮기고 스텐실 Comp/Pass를 켠다. ZWrite는 그대로 켜 둔다
- **스텐실 값은 렌더 상태라 MaterialPropertyBlock으로 못 바꾼다.** 슬라임마다 값이 달라야 해서 머티리얼 인스턴스를 쓴다. 풀링이라 인스턴스는 슬라임 오브젝트마다 처음 한 번만 생긴다
- 파티클 렌더러는 건드리지 않는다

### 카메라

슬라임과 캐릭터는 OverlayCamera(Main Camera의 Stack, Clear Depth)로, 땅은 Main Camera로 그린다. 씬 뷰는 카메라 스택과 컬링 마스크를 무시하므로 겹침 확인은 **게임 뷰에서** 한다.

---

## 4. 성능

- 드로우콜은 슬라임 하나당 머티리얼 수만큼(몸통 + 얼굴)이다. 슬라임마다 스텐실 값이 달라 슬라임끼리 배치로 묶이지 않는다
- SkinnedMeshRenderer라 GPU Instancing은 원래 불가다. 비용 대부분은 스키닝이다
- 몸통·얼굴을 텍스처 아틀라스로 합치면 드로우콜을 줄일 수 있으나 UV와 표정 교체 로직을 건드려야 한다

---

## 5. 아웃라인 (사용 안 함)

슬라임과 타워 모두 외곽선 없이 툰 셰이딩만 쓴다. `SlimeFlatKit`에서 `Outline` 패스와 외곽선 프로퍼티를 지웠고, 렌더러의 `Flat Kit Per Object Outline` 기능과 스무스 노멀을 굽던 `OutlineSmoothNormals`도 지웠다.

외곽선을 다시 넣는다면 아래 시행착오를 참고한다.

- **메시 외곽선(인버티드 헐)**: 메시를 노멀 방향으로 부풀린 뒷면을 그린다. 슬라임처럼 매끈한 한 덩어리는 잘 나오지만, KayKit처럼 여러 조각이 겹친 각진 캐릭터는 몸 안쪽에 조각마다 선이 생기고 모서리에서 갈라진다. 스무스 노멀은 FBX에 없어 런타임에 구워야 하고, 스킨드 메시는 그 노멀이 뼈를 따라 돌지 않는다
- **화면 외곽선(`Flat Kit Outline` 렌더러 기능)**: 깊이 차이로 화면 전체에 선을 긋는다. 모델 구조와 상관없이 깔끔하지만 맵·소품에도 선이 생기고, 깊이 텍스처와 전체 화면 후처리 비용이 든다. FlatKit 데모 씬을 열면 `AutoLoadPipelineAsset`이 데모 URP 에셋(이 기능 포함)으로 바꿔 놓아 화면 전체에 외곽선이 생기니, 비교할 때 주의한다

## 7. 검증 항목 (게임 뷰, Mobile 퀄리티)

- 겹친 슬라임이 교차선 없이 마리 단위로 갈리고, 먼저 나온 슬라임이 위에 보이는지
- 보스가 항상 일반 슬라임 위에 보이는지
- 몸통과 얼굴이 어긋나지 않는지
- 슬라임이 땅 표면에 서 있는지 (묻히지 않는지)
- 얼굴 눈·입 경계가 거칠지 않은지 (MSAA + AlphaToMask)
- 마릿수를 늘렸을 때 드로우콜 (Frame Debugger)

**검증은 Mobile 퀄리티 기준.** 실제 기기와 같은 포워드 렌더러다. PC 퀄리티(`PC_Renderer`)는 디퍼드라 화면이 조금 다르게 나올 수 있다.
