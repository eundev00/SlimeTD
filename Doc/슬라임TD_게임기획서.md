## 2. 핵심 컨셉

Bloons TD의 재미는 아래 두 축에서 나온다.
1. **경로를 따라 몰려오는 적을 다양한 타워 조합으로 처치하는 전략성**
2. **풍선이 레이어별로 터지며 작아지는 시각적 카타르시스 + 속성 상성**

슬라임 TD는 이 구조를 그대로 가져오되, **"터지는 풍선" 대신 "쪼개지는 슬라임"**이라는 소재 특성을 살린다.

- 슬라임은 풍선처럼 한 방에 사라지지 않고, **때릴 때마다 물컹하게 튕기며 반응**하다가 일정 데미지가 쌓이면 **더 작은 슬라임 2~3마리로 분열**한다 (풍선의 레이어 개념을 "분열" 메커니즘으로 재해석).
- 첨부된 리소스처럼 슬라임은 **재질(색상/속성) × 얼굴(성격/패턴)** 조합으로 무한에 가까운 종류를 만들 수 있어, Bloons의 "블루/레드/블랙/세라믹" 같은 속성 체계를 **훨씬 풍부한 비주얼로 확장**할 수 있는 것이 최대 강점이다.

## 3. 핵심 게임플레이 루프

```
웨이브 시작 → 슬라임들이 정해진 경로(Path)를 따라 이동
   → 플레이어가 배치한 유닛(타워)이 자동 공격
   → 슬라임 피격 시 넉백/찌그러짐 반응 → 체력 소진 시 "분열" or "소멸"
   → 경로 끝 도달 시 라이프 감소
   → 웨이브 클리어 → 골드/재화 획득
   → 골드로 신규 유닛 소환(랜덤) / 기존 유닛 성장
   → 다음 웨이브(난이도 상승, 새로운 슬라임 등장)
```

라이프가 0이 되면 게임오버, 전체 웨이브를 막아내면 스테이지 클리어.

---

## 3-1. 실패 조건

- **라이프 시스템**: 플레이어는 스테이지 시작 시 일정량의 라이프(생명력)를 보유한다
- 슬라임이 처치되지 않고 **경로 끝까지 도달**하면 라이프가 차감된다
- **라이프가 0이 되면 게임오버**
- 슬라임 종류별 차감량, 대장 슬라임 등 특수 개체의 차감량은 추후 밸런싱 단계에서 결정한다 (대장 슬라임은 별도의 특수 규칙 없이, 일반 슬라임보다 훨씬 큰 차감값을 부여하는 방식으로 위협감을 표현한다)

---
 
## 3-2. 성공 조건
 
- **스테이지 클리어**: 해당 스테이지의 마지막 웨이브까지 스폰이 전부 끝나고(더 이상 등장할 웨이브가 없고), 그 웨이브들에서 나온 슬라임이 전부 처리(처치 또는 경로 끝 도달)되면 스테이지 클리어로 판정한다.
- "마지막 웨이브의 스폰이 시작/완료됨" 자체는 클리어 조건이 아니며, 화면에 슬라임이 하나도 남지 않아야 클리어된다.

## 4. 슬라임 몬스터 디자인 — 7종 베이스 활용안

업로드된 리소스는 **7가지 슬라임 베이스 형태**(뿔 있음/없음, 귀 모양, 꼬리 유무 등)와 **재질(색상) 팔레트**, **얼굴 텍스처**가 분리되어 있어, 이를 조합해 Bloons의 풍선 등급 체계처럼 설계할 수 있다.

| 슬라임 속성(재질 기반) | 참고 색상 | 특징 | Bloons 대응 개념 |
|---|---|---|---|
| 기본 슬라임 | 흰색/베이지 | 낮은 체력, 기본 속도 | 레드 블룬 |
| 스피드 슬라임 | 노랑/주황 뿔 | 이동속도 빠름 | 옐로우 블룬 |
| 탱크 슬라임 | 갈색/뿔 큰 형태 | 체력 매우 높음, 느림 | 세라믹 블룬 |
| 냉기 슬라임 | 하늘색, 별 무늬 | 아군 타워 슬로우 디버프 부여 | — (신규) |
| 화염 슬라임 | 빨강, 뿔 | 화염 데미지 면역/반사 | — (신규) |
| 그림자 슬라임 | 검정/보라 | 은신(일부 타워에 안 보임) | 카모 블룬 |
| 보스 슬라임 | 무지개/대형 | 초대형, 이동속도 매우 느림, 처치 시 다량 분열 | MOAB 계열 |

**분열 메커니즘 예시**: 탱크 슬라임(대) → 피격 누적 시 기본 슬라임(중) 2마리로 분열 → 각각 추가 피격 시 미니 슬라임(소) 2마리씩 분열 → 완전 소멸. 이 "젤리가 쪼개지는" 연출 자체가 슬라임 소재만의 차별화 포인트다.

**얼굴 표정 시스템 활용**: 첨부 이미지의 다양한 표정(눈물, X자 눈, 하트 눈 등)을 상태 표시로 활용한다 — 예) 슬로우 디버프 걸리면 눈이 빙글빙글, 체력 낮으면 눈물 표정 등 → 별도 UI 없이도 상태를 직관적으로 전달할 수 있다.

## 5. 타워(유닛) 시스템

### 5-1. 획득 방식

타워는 **그리드 위 빈 칸(Cell)을 탭하는 행위가 곧 소환 트리거**가 된다. 별도의 "배치 모드" 진입/해제 없이, 유효한 칸을 탭하면 즉시 그 자리에서 골드를 소모해 무작위 타워가 소환·배치된다 (협동타워디펜스 방식 참고). 버튼만 누르면 빈 칸에 자동으로 배치되는 완전 자동 방식(운빨존많겜 방식)은 채택하지 않는다.

- 소환 재화는 별도 재화 없이 **인게임 골드**를 그대로 사용한다.
- 소환 결과(어떤 타워가 나오는지)는 **무작위**다.
- 이 방식은 타워 종류를 초기(1~3종)에는 적게 시작하되, 이후 지속적으로 확장(장기적으로는 수십 종 규모까지 고려)하는 방향과 맞물려 있다.

### 5-2. 재배치

이미 배치된 타워는 **클릭(터치) 후 드래그로 자유롭게 재배치**할 수 있다. 위치 제약(경로/장애물/다른 타워 점유 칸)만 지키면 재배치 횟수나 비용 제한은 없다. 타워를 클릭하면 해당 타워의 공격 사거리가 파티클 이펙트로 표시된다.

### 5-3. 성장 방식 — 미확정, 두 방향 열어둠

**방향 A — 합치기(머지)**: 같은 등급의 타워 2개를 유저가 수동으로(별도 버튼/메뉴 조작) 합쳐서 상위 등급 타워로 승급. 그리드에 단순히 올려놓는다고 자동으로 합쳐지지 않는다.

**방향 B — 단순 성장(레벨업)**: 합치기 없이, 개별 타워가 골드/재료 소모로 직접 레벨업. Bloons식 업그레이드 트리에 더 가까움.

두 방향 모두 5-1(랜덤 획득)과는 독립적으로 결정 가능하며, 최종 결정 전까지 타워 데이터 구조는 특정 방향에 과도하게 종속되지 않도록 설계한다.

### 5-4. 배치 판정 — 그리드 기반

맵은 셀(Cell) 단위의 그리드로 관리되며, 각 셀은 배치 가능(Placeable) / 배치 불가(Blocked) / 경로(Path) 상태를 가진다. 이미 타워가 점유한 셀에는 중복 배치할 수 없다. 자유 배치(Bloons TD 6식 픽셀 단위)는 채택하지 않는다 — 모바일 터치 정확도, 그리고 유사 캐주얼 게임(운빨존많겜 등)의 관례를 참고해 그리드 방식으로 확정했다.

### 5-5. 유닛 역할군 (기존안 유지)

| 유닛 유형 | 역할 | 예시 컨셉 |
|---|---|---|
| 단일 타격형 | 빠른 연사, 단일 대상 | 슬라임 사냥꾼(활/총) |
| 스플래시형 | 광역 데미지 | 슬라임 폭탄병 |
| 슬로우/디버프형 | 이동속도 감소 | 얼음 마법사 |
| 관통/라인형 | 일직선 다수 관통 | 레이저/화염방사 유닛 |
| 특수 처리형 | 은신/특수속성 대응 | 그림자 탐지 유닛 |
| 궁극기형 | 쿨타임 기반 필드 스킬 | 전체 슬로우, 전체 데미지 |

투사체는 발사 시점 타겟 위치를 향해 직진하는 논호밍 방식을 기본으로 한다 (Bloons TD 다트 참고 — 발사 후 추적하지 않으며, 경로상 다른 슬라임과 충돌 시 그쪽을 맞출 수 있음).

## 6. 진행/메타 시스템

- **재화**: 인게임 골드(스테이지 내 소모, 타워 소환에도 사용) + 프리미엄 재화(스킨/영구 강화)
- **슬라임 도감**: 처치/발견한 슬라임 조합을 도감처럼 기록한다 → 수집 동기 부여
- **슬라임 스킨 뽑기(선택적 BM)**: 재질×얼굴 조합을 활용해 "레어 슬라임 스킨"을 유닛 코스메틱으로 판매할 수 있다 (직접적 P2W보다는 수집/꾸미기 요소로). 타워 소환(5-1)과는 별도 체계로 유지하며, 재화 통합 여부는 추후 결정한다.
- **스테이지 진행**: 테마별 맵(숲/사막/빙하/화산) → 후반 맵일수록 해당 속성 슬라임이 대거 등장한다

## 7. 재미 포인트 (핵심 요약)

기획 시 이 부분에 가장 공을 들이는 것이 좋다. 우선순위 순으로 정리했다.

1. **말랑말랑 손맛 (Juice)** — 슬라임이 맞을 때마다 찌그러지고 튕기는 물리 반응, 분열 시 통통 튀며 갈라지는 연출.
2. **속성 상성 전략** — 색상=속성 체계를 명확히 해서 판단이 재밌게 작동하도록 설계한다.
3. **분열 체인 리액션** — 한 유닛의 광역 공격이 여러 슬라임을 동시에 쪼개고, 쪼개진 슬라임들이 다시 연쇄로 처리되는 콤보감.
4. **수집욕 자극** — 무한에 가까운 슬라임 커스터마이징 조합 + 랜덤 타워 소환을 "새로운 종류 발견" 경험으로 전환한다 (도감 완성 욕구).
5. **타워 빌드 전략성** — 랜덤 소환 안에서도 "이번 웨이브엔 이 타워가 유리하니 여기 배치하자"는 위치 선택 전략이 남아있도록 설계한다.
6. **보스/특수 웨이브 서프라이즈** — 거대 보스 슬라임 등장 시 화면을 가득 채우는 압도감 + 처치 시 대량 분열하는 카타르시스.
7. **경쾌한 코미디 톤** — 슬라임 표정을 활용한 유머러스한 리액션으로 캐주얼 유저 진입장벽을 낮춘다.

## 8. 아트 스타일 방향

- 첨부 레퍼런스처럼 **파스텔톤 + 둥글둥글한 실루엣 + 단순한 이모지 얼굴**을 유지한다
- **재질(Material) 레이어 + 얼굴(Face) 텍스처 레이어 분리** 시스템을 그대로 개발 파이프라인에 적용
- 배경/맵도 슬라임과 톤을 맞춘 로우폴리+파스텔 스타일을 권장한다

## 9. 향후 논의가 필요한 부분

- 정확한 플랫폼(모바일 단독 vs 멀티플랫폼)
- 수익모델 확정 (광고형 무료 vs 프리미엄 vs 하이브리드)
- **협동 모드**: 유력하게 고려 중이나 최종 확정 전까지 싱글플레이 기준으로 우선 개발한다. 고려 중인 구조는 맵을 플레이어별 독립 구역("Zone")으로 나누고, 각 Zone이 자체 웨이브 진행/골드/라이프를 독립적으로 갖는 방식이다 (협동타워디펜스 참고 — 서로 다른 진영에서 각자 적을 방어하며 공용 목표를 함께 지키는 구조). 라이프는 Zone별로 독립(공유하지 않음) 방향으로 가닥이 잡혀 있으나 최종 확정은 아니다. 네트워킹이 필요한 요소이므로 초기 빌드(싱글, 스테이지 3개) 완성 후 별도 로드맵으로 다룬다.

## 10. 웨이브 데이터 설계 원칙 (신규)

- 초반 웨이브(예: 1~10)는 기획자가 직접 하나하나 설계(수동 웨이브)한다.
- 그 이후 웨이브는 정해진 증가율(체력/마릿수 등)에 따라 자동으로 생성된다.
- 특정 웨이브 번호에 대장 슬라임이 등장하도록 별도 지정 가능하며, 수동/자동 구간 어디에든 겹쳐서 배치할 수 있다.
- 웨이브 전환은 기본적으로 이전 웨이브의 스폰이 끝나면 곧바로 다음 웨이브 대기시간에 들어간다 (이전 웨이브 슬라임이 화면에 남아있어도 무관 — Bloons TD 참고, 후반으로 갈수록 여러 웨이브의 슬라임이 겹쳐서 등장하는 물량감을 의도적으로 허용). 단, 스테이지의 마지막 웨이브만은 예외로, 슬라임이 전부 처리(처치/도달)된 후에 스테이지 클리어를 판정한다.
